## Run the initial diagnostic

Install uv, then use the declared Python 3.11.13 runtime. The base workspace has a small Pydantic runtime dependency through `canonical-sync`; Google client libraries remain optional under the explicit `drive` extra. From a checkout:

```sh
uv sync --all-packages --group dev
uv run --all-packages pytest -m 'not live_drive' -q
uv run llm-evaluation fixtures/e002_synthetic.json --k 2
uv run llm-evaluation fixtures/e002_synthetic.json --k 2 --output runs/local-e002-v3.json
```

The third command prints a **preview**. An installed wheel/console entrypoint also supports preview, but official finalization requires a fresh CLI process from a verified source checkout under an ordinary trusted Python startup/import environment. Low-level Python calls are utilities, not hostile-process attestation: v3 compares package files with Git blobs at finalization, and cannot attest monkeypatched functions or arbitrary code already in memory. The persisted `implementation_sha256` means the v3 package-source path/byte digest defined below; it is not an in-memory execution hash. An installed-wheel `--output` request exits with a clear checkout requirement. The fourth command requires a clean Git checkout, records the checked-out `HEAD` commit (including a GitHub PR synthetic merge commit when applicable) and the measured implementation digest, verifies its Python package bytes against the corresponding Git blobs, and creates the finalized v3 record once. It fails if the path already exists. An output made from a different checked-out code state must be a separate record. `runs/` is ignored: review public safety and provenance before deliberately promoting an artifact. The earlier ignored local v1 diagnostic, if present, is historical and does not meet the v3 finalization contract. Historical v2 records bound a commit using ordinary status, which could miss index-hidden modifications; neither v1 nor v2 establishes the v3 package-byte agreement.

The public fixture is synthetic. Its subject, prompt, harness, tool surface, runtime, sampling, retry policy, budget, benchmark, oracle, evaluator, and software identity are separate condition fields. The strict v3 finalization boundary requires a measured package digest matching the Git `HEAD` tree, a commit, Python runtime version, `fixture_raw_sha256` of the literal JSON file bytes, and `fixture_canonical_sha256` of sorted compact UTF-8 JSON plus terminal LF after parsing. An equivalent JSON file with different whitespace or key order has the same canonical digest but a different raw digest. `verify_result_source(result, source_bytes)` checks both hashes, condition, task counts, estimators, and aggregates against the supplied exact artifact. No standalone result proves an unavailable source. The identity digest covers sorted UTF-8 relative paths and literal bytes of every `.py` file under `src/llm_evaluation`, with length framing and a domain prefix; additions/removals change the inventory. Python caches are excluded. The writer rejects existing symlink path components, stages and fsyncs a complete file, publishes by an exclusive hard link, fsyncs the parent directory, and never replaces an existing path. Path checks do not promise race immunity against a concurrently hostile filesystem. A standalone record does not prove unavailable source or executing software; finalization checks both against its local checkout.

The [E-002 stopping-policy diagnostic](docs/e002-stopping.md) computes exact finite-horizon operating characteristics for synthetic Bernoulli decisions, including a deliberately invalid repeated-look control, conservative sequential rules, dependence/drift stress conditions, finite-reference error, and task-versus-generation variance. `llm-evaluation-stopping` previews the strict rational-number simulation record; its `--output` requires the same checkout-bound finalization. It makes no model calls and does not set a deployment threshold. The [portable model-runner preflight](docs/e002-portable-model-runner.md) adds an offline-tested OpenAI-compatible HTTP boundary, explicit capability gating and exact condition/request provenance. The separate [local runtime/model preflight](docs/local-runtime-preflight.md) freezes a tiny public objective task packet and comparison rules for runtime/model characterization. Both remain preflights and do not make E-002 RUNNING or COMPLETED.

This is a diagnostic of estimators, **not** a completed E-002 model experiment or a measured production reliability claim. For n observed binary trials, c successes and 1 <= k <= n, marginal success is c/n, best-of-k is 1 - C(n-c,k)/C(n,k), and all-k is C(c,k)/C(n,k). The latter two average events across size-k subsets of *observed* trials. Under independent identically distributed Bernoulli trials within a task, their sampling expectations are 1-(1-p)^k and p^k respectively. Correlation, drift, task selection, and deployment selection policies can break that future-run interpretation. Tests enumerate subsets as an independent oracle, exhaustively enumerate a small Bernoulli sample space, reject biased plug-in transforms, and include dependent and nonstationary counterexamples. Report costs separately when real sampling is added.

Historical formula lineage checked 2026-10-24: [HumanEval paper](https://arxiv.org/abs/2107.03374) and its [official pass@k implementation at b9453e8](https://github.com/openai/human-eval/blob/b9453e8f1865df0a0057a1383767caa400acfbcf/human_eval/evaluation.py); [τ-bench paper](https://arxiv.org/abs/2406.12045) and its [official all-k aggregation at 59a200c](https://github.com/sierra-research/tau-bench/blob/59a200c6d575d595120f1cb70fea53cef0632f6b/tau_bench/run.py). HumanEval marks its repository deprecated/unmaintained; the original τ-bench marks its tasks outdated and directs users to its successor. These pinned sources establish historical **formula lineage**, not current benchmark endorsement or independent benchmark validation. No upstream code or benchmark data was copied.

## Public publication threat model

A public PR can execute attacker-controlled tests and build code, so CI has no Drive or model credentials, uses the ordinary `pull_request` event, and requests only `contents: read`. Actions are pinned to reviewed commit identities; checkout does not persist Git credentials. Private acquisition is deliberately absent. A future credentialed job would require a separate trusted ref/workflow and restricted identity, with untrusted PR code unable to execute in that job. Local staging, raw model output, personal identifiers, and private Drive metadata (including IDs, revisions, names and hashes) can reveal information; ignored paths are only an accident barrier, not publication approval. Review the full diff and introduced history for secrets, proprietary content, redistribution rights and metadata before pushing. No service account, WIF provider, ACL change or paid infrastructure is provisioned here.
